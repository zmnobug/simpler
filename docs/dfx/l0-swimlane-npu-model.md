# L0 Swimlane NPU Model

## 1. Background

`l0-swimlane-npu-model` adds an NPU-side L0 view to the existing
L2 swimlane profiling flow. The goal is to make the AICore kernel
timeline visible in the same Perfetto trace that already shows L2
task timing and AICPU scheduler phases.

The first implementation intentionally uses the L2 per-task records
as the seed data source. Each collected AICore task span becomes one
L0 kernel-span event. This keeps the runtime integration small while
establishing the output schema, the host-side export path, and the
Perfetto visualization path.

The L0 marker path is deliberately runtime-owned: the AICore executor
records stable task/kernel-call boundary events around `execute_task()`.
Business kernel sources such as `add`, `matmul`, or paged-attention
kernels do not need to include profiling headers or insert marker calls.
Finer-grained NPU model events such as TPUSH/TPOP, pipe waits, or
instruction-like simulator events should be added from simulator /
intrinsic-level hooks or a replay flow, not by hand-editing every
operator implementation.

## 2. Scope

The feature is enabled together with L2 swimlane profiling:

```bash
python tests/st/<case>/test_<name>.py -p a2a3 -d 0 \
  --enable-l2-swimlane \
  --dump-tensor
```

Current platform coverage:

| Platform | Status | Notes |
| -------- | ------ | ----- |
| A2A3 sim | Supported | Emits L2, L0, merged Perfetto trace, and optional dump-args records |
| A2A3 onboard | Supported | Uses the same L2 collector export path |
| A5 sim | Supported | Emits the same L0 sibling file as A2A3 sim |
| A5 onboard | Not enabled yet | Existing L2 behavior is preserved |

The L0 output depends on L2 profiling. If `--enable-l2-swimlane` is
absent, no L0 records are exported. `--dump-tensor` is optional; when
enabled, dump-args entries can be correlated with L0 events by
`task_id`.

## 3. Output Layout

With `--enable-l2-swimlane`, the per-case output directory may contain:

```text
<output_prefix>/
├── l2_perf_records.json
├── l0-swimlane-npu-model.json
├── merged_swimlane.json
└── tensor_dump/
    ├── tensor_dump.json
    └── tensor_dump.bin
```

The files have separate roles:

| File | Role |
| ---- | ---- |
| `l2_perf_records.json` | Raw L2 profiling input: task timing, fanout, scheduler phases |
| `l0-swimlane-npu-model.json` | Raw L0 NPU model seed events, one kernel-span event per AICore task |
| `merged_swimlane.json` | Perfetto Chrome Trace JSON generated by `swimlane_converter` |
| `tensor_dump/tensor_dump.json` | Optional dump-args manifest; `args[]` can be matched to L0 events by `task_id` |

`swimlane_converter` keeps backward compatibility: if
`l0-swimlane-npu-model.json` is missing or has an unsupported schema,
the converter skips the L0 view and still emits the original L2 trace.

## 4. L0 Records Schema

`l0-swimlane-npu-model.json` currently uses schema version 1:

```json
{
  "version": 1,
  "time_unit": "us",
  "args_manifest": "tensor_dump/tensor_dump.json",
  "events": [
    {
      "name": "kernel",
      "task_id": 8589934592,
      "func_id": 0,
      "core_id": 2,
      "core_type": "aic",
      "subtask_id": 0,
      "start_time_us": 1.0,
      "end_time_us": 3.0,
      "duration_us": 2.0,
      "args_key": {
        "task_id": 8589934592
      },
      "kernel_events": [
        {"event_id": 1, "name": "task_ack", "timestamp_us": 0.9},
        {"event_id": 2, "name": "kernel_call_begin", "timestamp_us": 1.0},
        {"event_id": 3, "name": "kernel_call_end", "timestamp_us": 2.8},
        {"event_id": 4, "name": "finish_signal", "timestamp_us": 3.0}
      ]
    }
  ]
}
```

| Field | Meaning |
| ----- | ------- |
| `version` | Schema version, currently `1` |
| `time_unit` | Timestamp unit, currently microseconds |
| `args_manifest` | Relative path to dump-args manifest |
| `events[].name` | Raw event type; currently `kernel` |
| `events[].task_id` | Runtime task id shared by L2 records and dump-args records |
| `events[].func_id` | Kernel function id |
| `events[].core_id` | Physical/core index used for the Perfetto lane |
| `events[].core_type` | `aic` or `aiv` |
| `events[].subtask_id` | AIC/AIV slot id; currently AIC=0, AIV0=1, AIV1=2 |
| `events[].start_time_us` / `end_time_us` | L0 event span in the same time base as L2 |
| `events[].duration_us` | Event duration |
| `events[].args_key` | Correlation key for dump-args records; currently `task_id` |
| `events[].kernel_events[]` | Runtime-owned AICore boundary markers collected by the executor |

Current `kernel_events[]` names:

| Event | Meaning |
| ----- | ------- |
| `task_ack` | AICore has observed a task dispatch and is acknowledging it to AICPU |
| `kernel_call_begin` | Executor is about to call the task's `kernel_entry(args)` |
| `kernel_call_end` | `kernel_entry(args)` has returned to the executor |
| `finish_signal` | Executor has completed optional post-kernel barrier work and is about to finish the task |

## 5. Perfetto View

Open `merged_swimlane.json` in <https://ui.perfetto.dev/>. When L0
records are present, the trace includes an additional process:

- **AICore L0 View** — one lane per AICore, containing L0 kernel-span
  duration events.

The displayed L0 event name is resolved by `swimlane_converter`:

- If a `CALLABLE["incores"]` entry provides `name`, the trace uses
  that human-readable operator name. For paged attention this produces
  names such as `QK(r2t0)`, `SF(r2t1)`, `PV(r2t2)`, and `UP(r2t3)`.
- If no name mapping exists, the trace falls back to a stable function
  label such as `func_0_a(t0)`.
- The raw event type remains available in event args as `eventType`.

This makes the L0 view useful for operator-level inspection without
requiring every existing example to add display names.

## 6. Runtime Integration

The export path is implemented in the L2 perf collector:

```cpp
int L2PerfCollector::export_l0_swimlane_json();
```

The collector:

1. Reuses the already collected `L2PerfRecord` entries.
2. Converts each task span to an L0 `kernel` event.
3. Exports executor-owned `kernel_events[]` recorded without modifying
   business kernel sources.
4. Reuses the L2 base-time semantics and converts cycles to
   microseconds.
5. Writes `<output_prefix>/l0-swimlane-npu-model.json`.

The device runner calls this export after `export_swimlane_json()` on
the supported platforms. The converter then auto-discovers the L0
sibling file next to `l2_perf_records.json`.

## 7. Validation

Recommended checks:

```bash
python -m pytest tests/ut/py/test_swimlane_converter_l0.py -q

python examples/a2a3/tensormap_and_ringbuffer/vector_example/test_vector_example.py \
  --platform a2a3sim \
  --case TestVectorExample::default \
  --enable-l2-swimlane \
  --dump-tensor

python examples/a2a3/tensormap_and_ringbuffer/paged_attention/test_paged_attention.py \
  --platform a2a3sim \
  --case TestPagedAttention::CaseSmall1 \
  --enable-l2-swimlane \
  --dump-tensor

python examples/a5/tensormap_and_ringbuffer/paged_attention/test_paged_attention.py \
  --platform a5sim \
  --case TestPagedAttention::SmallCase1 \
  --enable-l2-swimlane \
  --dump-tensor
```

For each generated output directory, verify:

- `l2_perf_records.json` exists.
- `l0-swimlane-npu-model.json` exists and `events[]` is non-empty.
- `merged_swimlane.json` contains process name `AICore L0 View`.
- `kernel_events[]` contains runtime-owned boundary markers such as
  `kernel_call_begin` and `kernel_call_end`; it should not depend on
  paged-attention or any other operator source being manually instrumented.
- With `--dump-tensor`, `tensor_dump/tensor_dump.json::args[]`
  exists.
- L0 event `task_id`s match the L2 task ids. With dump args enabled,
  they should also match dump-args task ids after normalizing hex
  strings.

Expected smoke-test results from the current implementation:

| Case | L2 tasks | L0 events | Dump args | Expected L0 names |
| ---- | -------- | --------- | --------- | ----------------- |
| A2A3 vector default | 5 | 5 | 5 when `--dump-tensor` is enabled | `func_0_a`, `func_1_b`, `func_2_c` fallback labels |
| A2A3 paged attention `CaseSmall1` | 12 | 12 | 12 | `QK`, `SF`, `PV`, `UP` |
| A5 paged attention `SmallCase1` | 12 | 12 | 12 | `QK`, `SF`, `PV`, `UP` |

## 8. Limitations and Next Steps

- The current in-workload L0 view contains kernel spans and executor
  boundary markers, not instruction-level NPU model trace.
- L0 export currently follows `--enable-l2-swimlane`; there is no
  separate `--enable-l0-swimlane` flag.
- The dump-args correlation key is task-level only. A future schema can
  extend it to `(task_id, subtask_id, func_id)` if multiple in-task
  events need distinct arg records.
- A5 onboard is not wired to emit L0 records yet.
- Future extensions can add true NPU model events from simulator hooks,
  PTO intrinsic wrappers, or an Insight-style single-kernel replay flow
  while preserving the current sibling-file and converter behavior.
